# CdRescue

Windows-приложение для снятия образа с повреждённого CD с данными.

Читает сектора напрямую через SCSI pass-through (минуя файловую систему) и ведёт карту
секторов, как ddrescue. Работу можно прервать и продолжить позже, в том числе на другом приводе.

## Как работает

1. **Быстрый проход** — читает блоками по 64 КБ, при ошибке перескакивает вперёд
   (прыжок растёт до 4096 секторов), чтобы не мучить царапину.
2. **Доочистка** — возвращается к пропущенным областям и сужает их до отдельных секторов.
3. **Повторы** — на скорости 1x, каждый проход из двух фаз:
   - **чтение в обход кэша** (FUA): перед каждой попыткой головка отводится на 5000 секторов,
     на нечётных проходах назад, на чётных вперёд — к сектору подходим с разных сторон;
   - **сырое чтение**: READ CD отдаёт сектор целиком (2352 байта) вместе с флагами C2 — какие байты
     привод не смог исправить. Каждый сектор читается 3 раза за проход, копии складываются
     голосованием по большинству (байт без флага C2 весит вдвое больше), результат проверяется
     по контрольной сумме EDC сектора. Сошлась — сектор восстановлен точно.
     На время фазы привод переводится в режим «отдавать сектор даже с неисправимой ошибкой»
     (бит TB страницы восстановления ошибок) с одним собственным повтором; после — настройки возвращаются.

   Сектор, который так и не сошёлся по EDC, но хоть как-то прочитался, записывается в образ
   лучшей сборкой вместо нулей и отмечается на карте как «частично» (`~`). При следующем запуске
   такие сектора снова попадают в повторы. Если привод не умеет READ CD с C2, фаза пропускается.

   Скорость повторов чередуется: нечётные проходы на 1x, чётные на 8x. Программа задаёт её
   командой SET CD SPEED, а если привод не подтвердил — SET STREAMING (так же делает CDSlow),
   и пишет в журнал, что привод выставил на самом деле. Многие современные приводы принимают обе
   команды, но для чтения CD их игнорируют — так ведёт себя, например, ASUS SBW-06D5H-U
   (замер: 24x при любой заданной скорости). Для таких приводов программного способа замедлить
   диск нет; повторы всё равно полезны за счёт перепозиционирования и сырого чтения.

   После повторов скорость и настройки производительности привода возвращаются по умолчанию.

Каждые 10 секунд и при остановке образ сбрасывается на диск, затем сохраняется карта —
карта никогда не опережает образ.

Карта — текстовый файл, один байт на сектор: `?` не читался, `+` прочитан,
`-` плохой, `/` пропущен быстрым проходом, `~` восстановлен частично. Непрочитанные сектора в образе заполнены нулями.

## Проверка диска

Кнопка «Проверить диск» читает все сектора теми же двумя проходами, что и снятие образа
(быстрый с перескоком через повреждённые места, затем посекторная доочистка), но ничего
не записывает: ни образа, ни файла карты. Результат точный — каждый сектор либо прочитан,
либо отмечен плохим после отдельной попытки чтения; номера плохих секторов выводятся в журнал.
Повторов на минимальной скорости нет, поэтому часть «плохих» секторов может прочитаться
при снятии образа. По времени проверка равна полному чтению диска.

## Отчёт о повреждениях

Кнопка «Отчёт о повреждениях» разбирает файловую систему (ISO 9660 и Joliet) и сопоставляет
непрочитанные сектора с файлами. Отчёт строится в двух случаях:
- **после снятия образа** — по образу и карте, привод не нужен. Если образ неполный, краткий вывод
  появляется в журнале автоматически;
- **после «Проверить диск»** — образа нет, поэтому служебные сектора (дескрипторы тома, каталоги)
  читаются прямо с привода; их обычно несколько десятков, это занимает секунды. Так ещё до снятия
  образа видно, задеты ли нужные файлы. Если служебный сектор при проверке читался, а при анализе
  уже нет, отчёт об этом предупреждает.

В отчёте:
- где повреждения: в файлах, в служебных структурах (каталоги, таблицы путей, дескрипторы тома),
  в свободном месте, в системной области или за пределами файловой системы;
- какие файлы задеты: сколько секторов не прочитано или собрано частично и с какого смещения
  начинается первая ошибка;
- вывод: можно ли прожигать образ как есть. Если задеты только свободные места, данные целы.
  Если задеты файлы, копия будет читаться без ошибок, но с испорченным содержимым.

Служебные сектора разбираются, только если карта отмечает их прочитанными. Каталоги на большинстве
дисков записаны дважды (ISO 9660 и Joliet): если одна копия повреждена, файлы находятся по второй.
Диски только с UDF пока не разбираются. Отчёт сохраняется в текстовый файл.

## Запись на диск

Кнопка «Записать на диск…» записывает снятый образ на чистую болванку (CD-R/RW, DVD±R/RW, BD-R)
штатным API Windows (IMAPI2): оно само ведёт буфер и защиту от его опустошения. Диск закрывается,
дописать на него потом нельзя.

- В окне видно, какой диск вставлен: заводской диск, непустая или неподходящая болванка
  записываться не дадут, как и образ, который не помещается.
- Скорость — из тех, что привод поддерживает для вставленного диска; по умолчанию вторая сверху:
  на максимальной чаще бывают ошибки записи.
- После записи диск по умолчанию сверяется с образом посекторно, чтением мимо кэша привода.
- Неполный образ записать можно, но только после явного подтверждения: окно сразу показывает вывод
  отчёта о повреждениях. На копии повреждённые файлы будут читаться без ошибок, но с испорченным
  содержимым, и порча станет незаметной.

## Использование

1. Вставить диск, выбрать привод.
2. Указать файл образа (по умолчанию `%USERPROFILE%\CdRescue\<метка диска>.iso`);
   карта по умолчанию лежит рядом — `<образ>.iso.map`.
3. «Начать». Под полосой прогресса — фактическая скорость чтения и скорость, выбранная приводом;
   под легендой — сколько секторов показывает одна клетка карты. «Остановить» дожидается текущей команды чтения (до 20 с на плохом секторе)
   и сохраняет образ и карту.
4. Чтобы продолжить — указать тот же образ и ту же карту и снова нажать «Начать».

Обычно хватает прав пользователя. Если привод не откроется, программа предложит
перезапуститься от имени администратора.

## Сборка

Нужен .NET 10 SDK.

```bash
dotnet build -c Release
```

Один exe без установленного .NET (~50 МБ):

```bash
dotnet publish src/CdRescue -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o publish
```

## Структура

- `src/CdRescue/Rescue/` — логика восстановления: `CdDrive` (SCSI-команды), `SectorMap`, `Rescuer` (проходы)
- `src/CdRescue/MainForm.cs` — окно
- `src/CdRescue/SectorMapView.cs` — визуальная карта секторов
